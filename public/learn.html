01

Deliver real tool audit events

PostToolUse sends actual tool metadata as JSON to a per-run loopback HTTP receiver. Inspect the request body, response status and tool-use identifier. The local receiver is a classroom integration endpoint.

02

Handle HTTP failures and cancellation

Check response.ok because fetch does not throw for HTTP 503. Catch errors inside the integration callback. Pass AbortSignal to fetch and distinguish a short request deadline from an SDK hook timeout.

03

Run tracked background work

Return async output for logging-only side effects. Track and drain the actual background promise before collecting final evidence. The callback can return before delivery finishes; async hooks cannot retroactively block or modify execution.

04

Forward actual notifications

Keep a real Read review pending long enough for the SDK permission_prompt notification. Forward its actual message in a Slack-format text payload to the local receiver, then approve explicitly in the browser.

05

Compare event-specific timeouts

A one-second PreToolUse timeout blocks the read in the verified runtime. A one-second PostToolUse timeout keeps the successful tool result. Inspect actual abort signals and native SDK feedback.

06

Troubleshoot and track responsibly

Compare a file-name matcher that never fires with the correct Read matcher. Study the source-linked SubagentStop tracker as a reference. The app launches no subagents and makes no external Slack delivery.
